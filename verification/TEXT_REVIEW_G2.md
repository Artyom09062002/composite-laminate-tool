# G2 independent text audit

Reviewed 7 October 2026. Scope: app.py, ui_theme.py, presentation.py, report.py and reports/make_report_2.py. Read-only code audit by the reviewer. Findings below describe inspected wording; the parent implementation may subsequently apply the proposed corrections. Severity uses P1 for a consequential engineering overclaim, P2 for a local overclaim or misleading label, and P3 for style/clarity. No numerical value was changed by this audit.

1. **P2 overclaim — confirmed at inspection: netting burst labels.** app.py included `netting burst pressure peaks`, `Netting burst estimate [MPa]`, `Netting burst / working pressure`, and `Netting burst = 0` in the cylinder section. Correct wording: `fibre-only netting reference`, `Netting reference [MPa]`, `Netting / working pressure`, and `Netting reference = 0`. The surrounding limitations already distinguish fibre-only equilibrium from a real tank burst prediction, but the standalone metric labels should convey the same meaning. Mathematical pressure values and the +/-54.74-degree reference remain unchanged.

2. **P2 overclaim — confirmed, corrected in a subsequent inspected source: Alam implied-radius coincidence.** Report No. 2 initially said the model `matches the measured burst only if R is 45-52 mm`. The subsequently inspected paragraph states: `For Alam the separate calculated thresholds equal measured mean pressure at implied radii 45-52 mm. The radius is not reported in the supplied text, so this coincidence cannot be scored as validation.` This is appropriate: reverse-solving an unavailable geometry parameter does not validate first-ply, progressive stopping pressure or netting against measured burst.

3. **P2 overclaim — confirmed at inspection: sampled stack orders called bounds.** The Report No. 2 hybrid table status said `bounds: stack order unsourced`. The displayed interval comes from selected unsourced order scenarios; this audit did not establish that they exhaust all orders or bracket every possible result. Correct wording: `sampled stack orders, unsourced`, or `range across the tested unsourced stack orders`. Preserve the current numbers.

4. **P2 overclaim — confirmed at inspection: causal certainty about omitted liner.** Report No. 2 said a composite-only netting result of 0.26 of measured total was `as expected without the liner`. The omission supports a possible explanation, not the precise discrepancy magnitude or a causal partition of load. Correct wording: `The composite-only netting estimate is 0.26 of the measured total; omitted liner load sharing and incomplete geometry prevent attributing this gap to a single cause.` The nearby gain-over-bare-liner comparison appropriately says it is plausibility only because loads are not additive.

5. **P2 error/overclaim concern — rejected: test badges imply experimental validation.** ui_theme.py labels the suite `Checked by tests - recorded suite` and separately marks `Model assumption - see limits` and `Not validated against experiment`. The About text explains numerical/code checks versus experimental validation. This is a suitable distinction. Counts must continue to be recorded as baselines or actual successful runs, without implying live test execution when the app renders.

6. **P1 validation overclaim concern — rejected: validation_status.** presentation.py reports no like-for-like comparison when strict usable cases are empty, identifies missing inner-radius provenance and unmodelled Type III liner sharing, and says source pages remain unverified. Its alternative branch correctly says usable cases alone do not prove agreement. This review checked consistency with the supplied repository metadata, not the original papers.

7. **P1 ultimate-load overclaim concern — rejected: progressive metrics and PDF verdict.** The current app and compact report describe the last-ply value as the residual-stiffness algorithm's model stop and explicitly reject interpretation as validated ultimate/burst load. The cylinder chart explains held-pressure redistribution and absence of stability analysis. First-ply is described as calculated initiation. These are appropriate interpretations of the unchanged solver outputs.

8. **P1 scope error concern — rejected: thermal stresses silently included in exported or cylinder results.** app.py states thermal is restricted to the Failure thermal block. report.py marks sidebar loads as mechanical, separates the cylinder case, and lists thermal preload and dome strength as excluded from the compact export. Its verdict applies to calculated initiation under those reported loads, with reference strengths rather than qualified allowables. The distinction is visible in source text; this audit does not substitute for rendered layout QA.

9. **P2 stress-free provenance concern — rejected: current thermal UI and glossary.** The input requests `Assumed common stress-free temperature`; help explicitly rejects automatic equivalence with cure and rejects independent monolithic references as calibration of a co-cured hybrid. The glossary definition is consistent with the assumed zero-thermal-stress reference state. The direct delta-T mode applies the same increment to every ply and the caption states this. Source provenance was not independently reverified here.

10. **P3 style/clarity — confirmed: Report No. 2 historical next steps.** Its next-steps list still proposes thermal residual stresses and layup optimisation while the current app contains both. As a historically scoped C4 report this is understandable; the 7 October 2026 regeneration date could make it read as the current feature roadmap. Correct wording: `Thermal residual stresses and labelled cylinder layup screening were added after this C4 comparison; their verification is recorded separately.` Alternatively label the section `Next steps at the C4 baseline`.

11. **P3 clarity — confirmed: `results are valid only for a real ply-by-ply discretisation`.** In Report No. 2 this may sound like a positive validation claim. Correct wording: `Use physical ply layers; there is no fracture-energy regularisation, so discretisation-independent softening is not established.` It preserves the intended limitation without certifying an actual physical-ply result.

**Disposition:** No confirmed presentation claim warrants changing mechanics equations or defaults. Correct the four local overclaims/labels, retain the explicit experimental-validation failure and model-stop limitations, and preserve the existing numbers. Source verification and rendered PDF/UI QA remain separate checks.
